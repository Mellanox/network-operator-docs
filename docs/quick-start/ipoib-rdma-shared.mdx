<Note>
These manifests are the Kubernetes Launch Kit render for preset `GB200-NVL-NVIDIA-GB200` and release catalog `26.10` (`v26.10.0` component images on `nvcr.io/nvidia/mellanox`). East-west adapters on this preset are ConnectX-7 (`nicType` `1021`), which supports InfiniBand. BlueField-3 SuperNIC (`a2dc`) is Ethernet-only. The staging coordinates in `docs/common/vars.yml` are a separate release record. Multirail stays at the Launch Kit default, so each east-west rail is its own document in the pool and network files. Install the Network Operator chart before applying these custom resources. Helm `values.yaml` is omitted.

```bash
l8k generate \
  --for GB200-NVL-NVIDIA-GB200 \
  --node-selector "nvidia.com/gpu.product=NVIDIA-GB200" \
  --network-operator-release 26.10 \
  --fabric infiniband \
  --deployment-type rdma_shared \
  --skip-network-operator-helm \
  --save-deployment-files ./deployment
```

For the Launch Kit discover, deploy, and validate flow, see [Configuration Assistance with Kubernetes Launch Kit](/k8s-launch-kit/k8s-launch-kit).
</Note>

**Step 5**: Enable the Maintenance Operator

This example applies a `NicConfigurationTemplate`. The [Quick Start Helm install](/quick-start/quick-start-k8s#install-network-operator-helm-chart) leaves `maintenanceOperator.enabled` at its default `false`. Enable it before the template. NIC configuration changes that require node maintenance cannot finish without it.

```bash
helm upgrade network-operator nvidia/network-operator \
  -n nvidia-network-operator \
  --reuse-values \
  --version {{network-operator-version}} \
  --set maintenanceOperator.enabled=true
```

```bash

```

Run connectivity checks with the same bundle:

